# Code of conduct

## The short version

Be decent to people. Assume the person you are replying to is trying to make the project
better, and answer the argument rather than the person making it.

## Why this file exists at all

Most of what arrives here comes from someone whose website has been broken into, or who
suspects it has. They are usually not a security specialist, they are frequently
embarrassed, and they are often reading their own logs at three in the morning. A short
answer that makes such a person feel stupid costs the project the bug report it was about
to receive.

That is the practical reason. The ordinary reason is that harassment is unacceptable and
does not become acceptable because the code is good.

## What is expected

- **Answer the technical question.** "That is not how this works" is a fine opening as
  long as what follows explains how it does.
- **Say what you actually know.** This repository is unusually strict about the difference
  between what has been verified and what is assumed — see `DECISIONS.md` D-022. The same
  standard applies in a conversation: "I have not tested that" is a complete sentence, and
  a far better one than a confident guess.
- **Assume the report is real until the evidence says otherwise.** A user who cannot
  reproduce something on demand is not a user who is wrong.
- **Any language is welcome in issues and pull requests.** Committed artifacts are English
  (Principle VIII, and `CONTRIBUTING.md` explains why), and the conversation is not a
  committed artifact. Nobody should have to argue in a second language to report a bug.

## What is not acceptable

- Harassment, insults, or personal attacks, in public or in private.
- Sexualised language or imagery, and unwelcome attention of any kind.
- Discrimination or derogatory comments based on who somebody is: gender, gender identity
  or expression, sexual orientation, disability, physical appearance, body size, race,
  ethnicity, nationality, age, religion, or level of experience.
- Publishing anyone's private information — including paths, domains, IP addresses or
  logs from someone else's server that they did not choose to share. Reports here contain
  real infrastructure; treat what you see in them as confidential.
- Sustained disruption: reopening a settled decision without new argument, or demanding
  free support as if it were owed.

## Scope

This applies in the repository — issues, pull requests, code review, commit messages,
discussions — and anywhere someone is representing the project.

## Reporting

Report privately through
[a security advisory](https://github.com/thiagoluga/SentinelHost/security/advisories/new),
which is the one private channel this project has. Mark it clearly as a conduct report
rather than a vulnerability. If the report concerns the maintainer, GitHub Support can
escalate it independently.

Every report is read. What follows is proportionate and is decided by the maintainer: a
private word, a public correction, deleting a comment, or a block. Whoever reports
something is not required to keep participating in a thread while it is looked at, and
withdrawing from one is never held against them.

## A note on scope

This is a short document rather than an adopted standard text, so that everything in it is
something this project will actually do. If you would prefer the
[Contributor Covenant](https://www.contributor-covenant.org/) for its familiarity and its
shared enforcement vocabulary, that is a reasonable request — open an issue.
